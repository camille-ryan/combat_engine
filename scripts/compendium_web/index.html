Regex search over the compendium source

The pattern is a Python regular expression, not a word search. \d+, (a|b), \b, lookahead and backreferences all work. It is matched with re.search, so it does not have to match the whole field — anchor it with ^ and $ if you want that.

Three targets, OR-ed together. Name is the name column. Text is the card as printed text. HTML is the raw source markup, for when the question is about the markup — symbol/\d+a\.gif, or a tag that should not be there.

Each column header carries its own filter box. Those are regexes too, and they are AND-ed on top of the main pattern. An empty main pattern lists the whole category, so the column filters work on their own.

A pattern that does not compile shows the error in red. It never returns zero rows — a broken pattern must not be able to look like a true negative.

The repo column

What this repository made of each row: the ref if the ETL built it, plus any marker the hand-written content rows under it carry. (not built) means the ETL did not build it. Blank means there is no table for that category at all — it was never meant to be built, which is a different thing and reads differently on purpose.

Where the content comes from

Everything on this page is read live out of your own copy of the source database and the built database. Neither is in the repository, nothing is cached to disk, and the server is bound to loopback. The files that make up this tool hold no content of their own.
